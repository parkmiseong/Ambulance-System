# 검토용 경로 수정 후보 — 원본 미적용

아래 파일은 사용자 검토를 위한 후보입니다. 원본 SUMO 설정·경로·모델·manifest에는 연결하거나 적용하지 않았고, 시뮬레이션과 학습도 실행하지 않았습니다.

| 검증 항목 | 1단계: 출발·도착 유지 | 2단계: 남은 경로의 출발·도착 잘라내기 허용 |
|---|---:|---:|
| 원본 정상 경로 | 73대 유지 | 73대 유지 |
| 원본 문제 107대 중 누적 복구 | 1대 | 69대 |
| 전체 strict 검증 통과 | 74대 | 142대 |
| 미해결 차량 | 106대 | 38대 |
| 출발 edge 변경 | 0대 | 5대 |
| 도착 edge 변경 | 0대 | 63대 |
| 정상 73대의 edge 순서 변경 | 0대 | 0대 |
| repair를 끈 재검증 종료 코드 | 0 | 0 |

두 후보 모두 **180대 전체를 보존한 완성본은 아닙니다.** 후보 파일에는 통과한 차량만 포함되어 있으며, 180대 전체의 처리 결과와 미해결 ID는 각 단계 summary의 `vehicle_mapping`과 `missing_vehicle_ids`에 남겼습니다. 미해결 차량을 제외한 후보를 학습에 사용하는 결정은 하지 않았습니다.

1단계는 `amb_1120105`의 출발·도착을 유지하면서 중간 경로를 10개 edge에서 6개로 복구했습니다. 나머지 원본 정상 73대는 그대로 유지했습니다. 2단계는 1단계에서 해결하지 못한 차량에만 endpoint trim을 허용하여 68대를 추가했습니다. 그중 5대는 출발 도로가, 63대는 도착 도로가 변경되었습니다. 이 위치 변경은 아직 채택하지 않았습니다.

2단계 이후 미해결 38대 중 **34대는 원래 경로 전체에 emergency 허용 edge가 하나도 없어서**, 원래 경로 안의 허용 도로를 골라 시작·종점을 잘라내는 방식으로 복구할 수 없습니다. 나머지 **4대**(`amb_1106000`, `amb_1106101`, `amb_1106104`, `amb_1106201`)는 필수 도로 `454158885#0`에 도달할 수 없다는 native routing 오류가 남았습니다. 해당 차량을 모두 보존하려면 별도의 원점·목적지 또는 필수 경유 도로 변경 정책이 필요합니다.

도로 수 비교는 각 후보에 포함된 동일 차량의 원본과 비교했습니다. 1단계는 edge 출현 수 536→532, 고유 edge 71→68이며, 2단계는 1,216→697, 고유 edge 129→100입니다. 서로 포함 차량 수가 다른 두 단계의 총 도로 수를 직접 성능 비교한 값은 아닙니다.

후보 생성에서만 `--repair true`와 새 경로 계산을 허용했습니다. `--ignore-errors true`는 미해결 차량을 별도 집계하면서 복구 가능한 결과를 수집하기 위한 옵션이며, 최종 통과 판정은 별도 실행의 `--ignore-errors false --repair false --repair.from false --repair.to false --skip-new-routes true` 결과로 했습니다. 원본 정상 73대는 생성기가 제안하는 다른 경로가 있더라도 원래 경로를 사용했습니다.

차종 `emergency`, blue-light 양보 장치, 차량 ID·출발 시각·기타 차량 속성, 원본 vType 설정을 보존했습니다. 관리 구급차 최대 10대 규칙과 신호 특례를 바꾸는 코드·설정 변경은 하지 않았습니다. 원본 route·network SHA256도 실행 전후 동일했습니다.

후보가 정적 경로 검증을 통과한 것은 확인했지만, 이 후보를 사용하면 27회차 native 충돌이 사라진다고 검증한 것은 아닙니다.
