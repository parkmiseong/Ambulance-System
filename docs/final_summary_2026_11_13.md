## 1. 웹에서 프로젝트 실행

`start_dashboard.bat`를 실행하면 <http://127.0.0.1:8000>에서 사용할 수 있다. 서버가 실행 중이었다면 먼저 종료하고 다시 실행한 뒤 브라우저를 새로고침한다.

```powershell
.venv/Scripts/python.exe -B CODE/web_dashboard.py
```

| 화면 | 완료한 내용 |

| 오른쪽 실행 설정 | 학습·시뮬레이션, 시작·일시정지·재개·중지, 실행 배속 |
| 시나리오 | 도로 상황·환자 발생률·병원 혼잡도를 각각 3단계로 선택하는 27개 조합 |
| 보상 | 누적·환자당 보상, 연구용 골든타임 내 도착, 실패·수용 거절 수, 보상 항목별 분해와 그래프 |

| 가상 병원 | 학습·시뮬레이션 모두 0개 또는 2~10개. 생성 시 권역 2개 기본 + 나머지 세 유형 비율 조절. 공통 병원 평가 DQN은 가중치 유지, 구형 flat_v3는 원래 수 유지 |

## 2. 환자별 중증도와 이송 병원

사용자가 제공한 MI Lab PDF의 환자·병원·구급차 상태와 이송 흐름을 참고해 다음을 연결했다.

- 환자 ID, 보고 시 Pre-KTAS, 배정 KTAS, 구급차 ID, 배정 병원과 유형.
- 도착·실패·관측 종료, 대기·이송·총 소요 시간, 발생·배정·종료 시각.
- 배정 당시 병원 점유율·적합도, 환자별 실제 보상과 항목별 내역.
- 중증도별 집계와 병원×KTAS 도착 환자 수. 도착하지 않은 환자는 병원 도착 수에서 제외.
- 에피소드·중증도·병원·결과·검색 필터, 페이지 조회, 전체 필터 결과 CSV.
- 실행 중 확정된 모든 환자 기록, 이전 실행 불러오기, 전체 결과 JSON.

119/소방 지점은 참고 위치다. 현재 구급차는 환자 위치에서 생성되어 병원으로 이동하며, 센터 출동·복귀를 구현한 것은 아니다. 생존율·사망률이나 임상 결과를 새로 추정하지 않는다. 자료의 제안과 현재 구현 범위는 [자료 반영 기록](reference_dashboard_review.md)에 구분했다.

## 3. 강남 기준 환자 발생률 보정

후속 요청으로 **환자 수 직접 입력**도 추가했다. 실행 설정에서 강남 기준·시간당 직접 입력·고정 총 인원 중 선택한다. 고정 인원은 회차마다 정확히 지정한 수를 발생시키고, 시간당 인원은 기대 발생률이다. 상세 범위와 예시는 [웹 사용 안내](web_dashboard.md#환자-수-직접-입력)를 참고한다. 아래의 통계 기준은 강남 기준 모드에만 적용한다.

기존 웹 기본값 `초당 0.3`은 시간당 기대 환자가 1,080명이었다. 이를 시간당 수요로 보정했다.

근거는 강남구 [제40회 강남통계연보(2024년 기준)](https://www.gangnam.go.kr/board/B_000645/1068850/view.do?mid=ID02_01020902) 6쪽의 **119 구급활동 46.6건/일**이다. `46.6 / 24 = 약 1.94건/시간`을 대리 기준으로 사용한다.

| 환자 발생 설정 | 시간당 기대 인원 | 기준 대비 |
|---|---:|---:|
| 여유 | 약 1.94명 | 기준 |
| 보통·기본 | 약 2.14명 | +10% |
| 혼잡 | 약 2.33명 | +20% |

구급활동 1건을 가상 환자 1명으로 대응한 모델링 가정이다. 실제 전체 환자 발생 수나 이송 인원의 직접 측정값은 아니며, 연평균으로부터 계산했으므로 시간대별 변동도 반영하지 않는다.

초당 발생 확률은 `시간당 수요 / 3600`이다. 기본 발생 기간은 3,600초, 최대는 86,400초이며 화면에서 시간당 수요·선택 기간의 기대 환자 수·공식 출처를 확인한다. 실제 수는 시드에 따라 달라지고 짧은 실행에는 0명일 수 있다. 재생 배속을 바꿔도 시뮬레이션 시간당 수요는 달라지지 않는다.

근거·가정·배율은 `DATASET/gangnam_ems_reference.json`, 변환은 `CODE/dashboard_demand.py`에 저장했다. 기존 CLI의 고밀도 연구 시나리오는 그대로 유지한다.

## 4. 실제 구급차 양보

**구급차 우선 통행·양보** 옵션을 추가했고 기본 ON이다.

- SUMO blue-light 장치와 횡방향 해상도 0.4m, 반응 거리 60m를 적용.
- 맨 왼쪽 차로 차량은 왼쪽, 나머지 차로 차량은 오른쪽으로 이동해 통로 형성.
- 지도에 실제 주변 차량 위치를 표시하고 SUMO `rescueLane`에서 연구용 구급차에 반응한 차량만 황색으로 표시.
- 주변 양보 차량 수, 차량 선택 시 양보 대상 ID, 구급차 포커싱 목록과 지속 카메라 추적 제공.
- 연구용 구급차 주변 100m 내 최대 150대만 표시. 양보 수는 이 범위의 현재 수이며 전체 도로망·누적 수가 아님.
- 학습과 고정 검증에 동일한 ON/OFF 조건을 사용하고 실행·학습 기록에 설정 저장.

이 옵션은 적색 신호 특례와 긴급 차로 변경도 포함한다. 따라서 ON/OFF 비교를 ‘양보만의 효과’라고 해석하지 않는다. 실제 통행 가능 여부는 도로 폭·교통량·반응 시점 등에 따라 달라진다. [SUMO 긴급차량](https://sumo.dlr.de/docs/Simulation/Emergency.html)과 [차로 내 이동 모델](https://sumo.dlr.de/docs/Simulation/SublaneModel.html)을 사용한다.

원본 배경 교통 데이터는 1시간 분량이다. 웹에서는 장시간 실행과 마지막 환자의 이송 마무리 구간에도 차량 유입이 이어지도록 승용차 trip 패턴을 3,600초 간격으로 반복한다. 원본 파일은 수정하지 않고 실행별 파일을 생성한다. 원본 해시·반복 주기·생성 수를 기록하며, 시간대별 실측 교통량이 아닌 반복 가정임을 명시했다.

## 5. 최종 점검에서 추가 수정한 부분

| 문제 | 수정 결과 |
|---|---|
| 검증으로 전환되면서 SUMO 시각이 같으면 이전 차량이 지도에 남음 | 프레임 변경 번호를 추가해 종료된 차량·주변 교통 즉시 제거 |
| 실행 프로세스가 예상 밖으로 종료되면 지도에 차량이 남음 | 오류 상태로 전환하고 운행·양보 표시 정리 |
| 이전 실행의 늦은 이벤트가 다음 실행 상태를 변경할 수 있음 | 이벤트를 보낸 프로세스와 현재 실행의 일치 여부 확인 |
| 필터를 빠르게 바꿀 때 이전 결과 응답이 표시될 수 있음 | 필터 변경 즉시 이전 요청을 무효화 |
| 다른 실행의 깨진 manifest 하나가 전체 결과 조회를 막음 | 무관한 손상 파일은 건너뛰고 선택한 실행의 오류는 읽기 쉬운 메시지로 반환 |
| 창 크기가 바뀌면 구급차 확대가 풀림 | 사용자가 확대한 중심·배율 유지 |
| 낮은 수요로 실제 학습이 0회인데 완료만 표시 | 학습 예상 환자 수와 실제 누적 가중치 업데이트 수, 0회 안내 표시 |
| 검증 환자 0명을 보상 0점으로 취급하거나 초기 가중치를 best로 선정 | 가중치 업데이트와 검증 환자가 모두 있는 모델만 새 best 후보로 선정 |
| 웹 학습의 고정 검증 시드가 실험 기록에 없음 | `기본 시드 + 50000`을 명시적인 `validation_seeds`에 저장 |
| 1시간 뒤 배경 차량 유입 종료 | 웹에서 원본 승용차 패턴을 반복해 이송 마무리 구간까지 유지 |

기본 보통 수요·1시간·3에피소드의 기대 환자는 약 6.4명이다. 기본 첫 학습 배치 32개 경험을 채우지 못할 수 있다. 환자 발생률을 다시 높이지 않고, 학습 기간이나 에피소드를 늘려 경험을 확보하도록 안내한다. last·체크포인트는 남기되 업데이트가 없거나 검증 환자가 없으면 새 best는 만들지 않는다.

수정 전에 저장된 모델과 결과는 변경하지 않았다. 과거 웹 모델의 검증 시드 기록이 없는 경우, 그 파일만으로 검증·평가 시드 분리를 입증할 수 없다는 제한은 남는다.

후속 요청으로 시뮬레이션의 가상 병원 수 변경과 카메라 추적도 추가했다. v4·v5·v6 공통 병원 평가 가중치를 보존하고 새 병원 수로 평가하며, 원본 모델은 변경하지 않는다. 구급차 포커싱 목록에서 차량을 선택·전환하고, 추적 해제·지도 드래그·전체 보기로 종료한다. 차량 운행 종료 시 추적도 종료한다. 자세한 사용법과 구형 v3 제약은 [웹 안내](web_dashboard.md)에 정리했다.

가상 병원 유형도 조절하도록 확장했다. 권역 2개는 고정하고 나머지를 지역센터·지역기관·신고기관 비율로 나눈다. 초기값 5:4:1은 사용자 설정값이며 실제 통계 추정치가 아니다. 정수 배분·생성 예정/실제 개수 표시·설정 저장을 연결했고, 총수 변경 없이 유형만 바꾼 DQN 평가도 지원한다. 새 웹 생성은 0개 또는 2~10개이며 기존 CLI 배치 기본값은 보존했다.

병원 거절 패널티는 최종 요청에 따라 **실제 병원 도착 후** 부여하도록 수정했다. 웹의 **병원 도착 후 거절 패널티**는 기본 ON이다. 사전 수용 확인으로 가능한 병원을 고르되 이동 중 병상을 예약하지 않는다. 실제 도착 시 병상 부족·수용 중단으로 거절된 경우에만 1회당 **-12점**을 부여한다. 같은 구급차와 환자를 유지하고 현재 병원 위치에서 다른 병원까지 실제 재이송한다. 대안이 없으면 병원에서 기다리며 반복 상태 확인에는 벌점을 추가하지 않는다. 최초 출발 이후 추가 이동·병원 대기는 모두 이송 시간에 포함한다. 사전 문의·응답에 별도 통화 시간을 가정하지 않는다.

병원 현황의 내부 스크롤·높이 제한을 없애 전체 목록을 펼쳤다. 실행 설정은 제목의 접기·펼치기로 조작하며 배속·실행 버튼·진행 상태는 계속 표시한다. 새로고침 후에도 접힘 상태를 유지하고 잘못된 입력이 있으면 자동으로 펼친다.

병원별 혼잡도 보상은 사용자 선택에 따라 **여유 병원 가점·혼잡 병원 감점**으로 확장했다. 배정 직전 해당 병원 점유율을 `o`로 두고 `8 × (1 - 2o) - 5 × max(o - 0.7, 0) / 0.3`으로 계산한다. 20%는 +4.8점, 50%는 0점, 80%는 약 -6.47점이다. 현재 웹은 이동 중 예약 없이 배경·치료 중 환자를 반영하고, 기존 예약 방식은 다른 환자의 예약 병상도 포함한다. 학습·검증·시뮬레이션·후보 예상 보상에 같은 방식을 적용한다. 병원 현황은 현재 참고 점수, 환자 상세·CSV는 실제 적용 점수와 배정 시 비율을 보여 준다. 기존 CLI·과거 manifest는 원래 감점 방식으로 재현하며 새 방식은 `balanced`로 기록한다.

실제 거절은 학습 전이에 즉시 반영하고 환자 최종 보상에 중복 차감하지 않는다. 보상 패널에 횟수·거절 비용, 환자 상세에 방문 병원 순서·출발/도착 시각·사유·점수, CSV·JSON에 전체 방문·거절 이력을 저장한다. 실패와 관측 종료에도 이미 발생한 거절 비용은 유지한다. OFF와 기존 CLI 기본값은 과거 사전 검사·예약 방식이며 새 CLI에서는 `--admission-mode arrival`로 켠다. 이전 `request`는 과거 출발 전 요청 실험 재현용이다. 수용 방식이 다른 평가를 한 집계로 합치지 않는다. 기존 모델로 옵션을 켜는 것은 조건을 바꾼 평가이며, 새 동작을 학습한 모델이 필요한 경우 새로 학습한다.

- 골든타임 여유와 병원 후보 예상 보상을 각각 켜고 끄는 대조군 제공. 미래 실제 결과는 관측에 사용하지 않음.
- best 모델 평가, 학습·검증·평가 시드 분리, 보상 분해와 환자 대응 비교, 시드 단위 신뢰구간.
- 기존 v3·v4·v5 모델은 원래 관측과 네트워크로 평가.

별도로 실행한 기존 CLI 실험 `results/v6_s6_updates_s42`의 저장 로그에서 **54에피소드 완료, 누적 업데이트 1,540회**를 확인했다. 저장된 best는 **36회차**, 당시 누적 업데이트 1,007회이며 고정 검증 환자당 보상은 약 **-15.368점**이다. best와 마지막 모델의 회차는 다르다.

이 실험은 기존 CLI 수요·교통 조건이다. 이번 웹의 통계 보정 수요·양보 조건으로 학습한 결과와 섞어 비교하지 않는다. 이 검증 점수만으로 정책 성능 향상이나 임상적 효과를 결론 내리지 않는다. 실험 명령과 비교 방법은 [v6 구현·실험 안내](v6_implementation_2026_11_13.md)를 따른다.

## 7. 결과 파일과 실행 범위

새 웹 실행은 `results/web_dashboard/<실행 ID>/`에 저장한다.

| 파일 | 내용 |
|---|---|
| `run.json` | 선택 설정, 병원 구성, 수요 출처·배율, 배경 교통 가정, 양보·수용 요청 설정 |
| `experiment_history.csv` | 환자별 확정 결과, 실제 병원 거절 사건과 에피소드 로그 |
| `patients_episodeN.json` | 완료 에피소드의 모든 환자 상세 |
| `episodeN.json` | 보상·학습·검증 집계 |
| `experiment.json` | 새 학습 구성·관측·병원·검증 시드·서명 |
| `models/*_last.pth`, `checkpoint.pth` | 최신 가중치와 전체 학습 상태 |
| `models/*_best.pth` | 실제 업데이트와 유효 검증을 충족한 best만 생성 |
| `background_repeated.trips.xml` | 1시간 이후의 반복 승용차 수요 |

환자별 상세 CSV와 현재 실행의 전체 JSON은 화면에서도 내려받는다. 한 서버에서 한 실행을 지원하며 로컬 주소에 바인딩한다.

외부 배포는 구조 검토 단계다. 실제 공개 URL·클라우드 서버·도메인 배포는 수행하지 않았다. SUMO 실행 파일, Python·PyTorch, 결과·모델 영구 저장소를 갖춘 실행 서버가 필요하므로 정적 웹 파일 배포만으로 현재 시뮬레이션이 작동하지는 않는다.
