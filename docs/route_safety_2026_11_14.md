# 2026-11-14 구급차 경로·병원 정차 검사

사용자가 보고한 실행 `20261113_221013_bafb5e`에서는 15명 중 1명이 `hospital_stop_missing`으로 실패했다. 해당 차량 `amb_eval_6`의 실제 SUMO 기록은 경로 길이 1,117.09m, 대기 301초, `vaporized=teleport`였다. 병원 접근 도로 `913389303`의 1번 차로에 도착했지만 정차는 0번 차로로 강제되어 있었다. 단순히 경로가 없었던 사례와 정차 차로 문제가 섞이지 않도록 원인을 구분했다.

## 변경

- `emergency` 차량이 통과할 수 있는 차로 연결을 사용해 방향 그래프를 검사한다. 통행 가능 도로 15,762개 중 주 강연결 성분은 15,363개이며, 밖의 도로는 399개다. 이 399개 전체가 잘못된 도로라는 뜻은 아니며 일방통행 진입·말단 도로도 포함한다.
- 현재 웹의 도착 후 수용 판정(`arrival`)은 재이송까지 지원하므로 주 연결망 안에서 환자 발생 도로와 병원 접근 도로를 선정한다. 병원 슬롯·모델 가중치·원본 도로망 파일은 유지한다. 접근 불가 병원은 경로 후보에서 제외한다. 중증 환자용 병원 접근 도로 또는 환자 출발지가 없으면 실행 준비 단계에서 설명과 함께 중단한다.
- 각 출발·재이송 결정에서 실제 TraCI 경로와 `emergency` 차로 연결을 확인한다. 병원 정차 차로는 경로의 마지막 연결에서 진입 가능한 차로 중 고른다. 구급차 양보 장치가 왼쪽 주행을 선호하므로 가능한 경우 가장 왼쪽 정차 차로를 사용한다.
- 재이송 첫 회전은 정차 중인 실제 차로에서 가능한 연결만 허용한다. 기본 경로가 그 차로와 맞지 않으면 가능한 첫 회전으로 시작하는 대체 경로를 검사한다. 검사된 접근 도로가 없는 병원으로 출발하지 않는다.
- 기존 CLI의 `precheck`·`request` 실험은 이전 계산 방식을 유지한다. 새 필터로 환자 출발 도로·경로가 달라질 수 있으므로 이전 실행과 완전히 같은 조건의 성능 비교로 해석하지 않는다. 실행 결과 `route_safety`에 검사 방식·도로 수·병원별 접근 도로 수를 기록한다.

실제 지도 근거 없이 교차로·교량·일방통행을 임의로 연결하는 대신, 검사된 도로망을 사용하는 방향으로 수정했다. 이 검사는 정적인 연결·차로 허용과 정차 접근을 확인하며 교통 정체, 병상 부족, 이송 제한시간 초과까지 모두 없애는 보장은 아니다.

## 검증

- 문제의 출발 도로 `-31755403#4`, KTAS 5, 원래 v5 DQN, 양보 ON을 사용한 재현에서 같은 병원에 67초 만에 도착했다. 결과는 `results/verification/route_safety/replay.json`에 저장했다. 시작 시각은 1초로 옮긴 단일 환자 재현이므로 원 실행과 교통 상태까지 동일한 대조는 아니다.
- 원래 웹 실행 설정(15명/시간, 1시간, 보통 교통, 양보 ON, 동일 모델·가상 병원 설정)을 재실행하는 검증은 `tests/verify_route_safety.py`다. 결과는 `results/verification/route_safety/full-run-proof.json`에 저장한다.
- 전체 재실행 결과는 **발생 15명·도착 15명·실패 0명·관측 중단 0명**이다. 출발 후보 1,200개 중 주 연결망에 속한 1,192개를 사용했다. `A1100004`는 기존 접근 도로 후보 12개가 주 연결망 밖이어서 이번 실행의 선택 후보에서 제외됐다. 원본 병원 슬롯은 유지했다.
- 방향 단절·일방통행 말단, 도착 차로, 재이송 첫 회전, 대체 경로, 검사 실패 시 준비 중단을 `tests/test_route_safety.py`에서 확인한다.
- 실제 SUMO의 도착 후 거절·동일 차량 재이송 검증(`tests/verify_arrival_rejection.py`)도 통과했다.
- 전체 Python 회귀 테스트 **208개 통과**. 종합 기록은 `results/verification/route_safety/verification.json`에 저장했다.

```powershell
.venv/Scripts/python.exe -B -m unittest discover -s tests -q
.venv/Scripts/python.exe -B tests/verify_route_safety.py
```

Python 서버를 재시작한 뒤 새 실행부터 적용한다. 기존 저장 결과를 덮어쓰거나 실패를 성공으로 바꾸지 않는다.
