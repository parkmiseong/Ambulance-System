## 재개 명령의 동작 — 원인 확인 후 사용

아래 명령은 남은 횟수를 계산하는 기능을 유지합니다. **현재 동일 충돌을 피할 수 있다고 확인한 명령은 아니므로, 원인 확인 전 실행을 권장하지 않습니다.**

```powershell
.venv/Scripts/python.exe -B -u CODE/resume_sumo128.py
```

이 명령은 저장된 실험 설정을 복원하고, 검증한 portable 엔진을 해당 Python 프로세스에서만 선택합니다. 시스템 환경 변수와 기존 설치는 변경하지 않습니다.

- 현재 새 폴더의 체크포인트: **26회 완료, 실제 가중치 업데이트 342회**입니다. 원본 폴더는 24회·292 업데이트를 유지합니다.
- 현재 체크포인트 기준 재개 범위: **27~45회**, 추가 19회입니다. 실행할 때마다 체크포인트를 읽어 누적 목표 45회까지 남은 횟수를 계산합니다. 충돌 대응을 적용하기 전에는 다시 같은 회차에서 중단될 수 있습니다.
- 출력 폴더: `results/all_scenarios_normal15_yield_repeat_sumo128_v6`입니다.
- 기존 폴더: `results/all_scenarios_normal15_yield_repeat_v6`는 보존합니다.
- 검증: `--eval-every 45`에 해당하며, 정상 완료 시 45회에서 저장된 검증 패널로 best를 선정합니다. 검증 패널은 시나리오 9개 × 시드 3개이므로 학습 한 회보다 오래 걸릴 수 있습니다.

현재 26회 체크포인트에서 실행하면 다음 내용이 표시됩니다. 이는 명령의 계산 예시이며, 27회차 통과가 확인되었다는 뜻은 아닙니다.

```text
[Resume] previous=26 additional=19 target_total=45
[Resume] SUMO=1.28.0 output=...all_scenarios_normal15_yield_repeat_sumo128_v6
[Training] previous=26 episodes | additional=19 | target_total=45
```

저장된 조건은 시나리오 1~9 순환, 수요 단계별 시간당 기대 환자 10/15/20명, 환자 발생 기간 3,600초, 구급차 10대, 가상 병원 0개, 도착 시 입원 판정, balanced 점유율 보상, 긴급차 양보 ON, 배경 교통 반복 ON입니다. 학습 seed 42, gamma 0.95, 타깃 동기화 200 업데이트, 검증 시드 30001/30002/30003도 유지합니다. 매회 실제 발생 인원은 기대 인원과 다를 수 있습니다.

재개 준비 당시 원본 24회 체크포인트에서 replay·optimizer·epsilon·RNG를 복원해 다음 에피소드 하나를 진단 실행했습니다. 이 진단에서 진행한 가중치 업데이트는 저장하지 않았습니다. 아래의 **진단 환자 26명 도착**은 위 표의 **실제 학습 25회차 환자 24명 도착·2명 실패**와 구분해야 합니다. 진단 1회 통과로 후속 회차 전체의 안정성을 검증한 것은 아닙니다.

## 엔진과 실험 이력 보존

공식 배포본 `sumo-win64-1.28.0.zip`의 전체 SHA256을 확인하고 프로젝트의 `.runtime/sumo-1.28.0`에 실행 파일과 도구를 분리했습니다. 설치 프로그램과 전역 패키지 변경은 사용하지 않았습니다. `.runtime`은 Git에서 제외합니다.

- ZIP SHA256: `822aa9c57a07a895200d536fd2b3fe8785e36baa9b97ecbe75688e08a636fb8e`
- 새 `sumo.exe` SHA256: `35d45c1166ceb5b72cce37676216f79124fcfe05920a496b14daee19acdaf9f3`
- 공식 배포 파일: [SUMO 1.28.0 Windows ZIP](https://sumo.dlr.de/releases/1.28.0/sumo-win64-1.28.0.zip)

새 출력 폴더의 `engine_transition.json`에 **1~24회는 SUMO 1.27.1, 25회부터는 SUMO 1.28.0**이라는 이력을 기록했습니다. 이 모델은 처음부터 단일 엔진으로 학습한 모델이 아닙니다. 교수님께 결과를 제출하실 때 이 전환을 함께 기재해 주세요.

원본 학습 이력과 best를 새 폴더로 합치지 않았습니다. 현재 원본에는 아직 best가 없으며, 새 엔진에서의 검증 후 best가 생성됩니다. 재개용 full checkpoint에는 누적 회차·replay·optimizer·탐색률·RNG가 보존됩니다. 저장 시 manifest 참조는 새 폴더를 가리키도록 보완했습니다.

재개 명령은 엔진 SHA256을 검사합니다. 별도로 `train_agent.py --resume`를 사용하면서 기존 엔진이 선택되면 학습을 시작하기 전에 오류를 표시합니다. `.runtime/sumo-1.28.0`을 삭제하거나 엔진 파일을 바꾸지 마세요.

## 학습 완료 후 평가

아래 명령은 **충돌 대응 후 45회 학습과 best 선정이 완료된 뒤** 실행해 주세요. 현재 26회 상태에서는 best가 아직 없습니다. PowerShell에서도 새 엔진을 선택해야 학습 후반부와 같은 엔진에서 평가합니다.

먼저 `models/dqn_v6_f560a1f65da40cc8_best.pth`가 생성되었는지 확인해 주세요. 45회 학습 직후 검증만 실패했다면 체크포인트는 45회여도 best는 없을 수 있습니다. 재개 명령은 이미 달성한 학습 목표를 다시 수행하지 않으므로, 이 경우에는 실패한 검증을 별도로 다시 수행해야 합니다. best가 없다고 last 모델을 최종 평가 모델로 대체하지 않습니다.

```powershell
$env:SUMO_BINARY = (Resolve-Path '.runtime/sumo-1.28.0/bin/sumo.exe').Path
.venv/Scripts/python.exe -B -u CODE/run_scenarios.py `
  --output-root results/all_scenarios_normal15_yield_repeat_sumo128_v6 `
  --scenario 0 --strategies shortest_time,heuristic,greedy_reward,dqn --quiet
```

웹에서도 같은 엔진을 사용하려면 위 환경 변수를 설정한 PowerShell에서 웹을 실행해 주세요. GUI 엔진을 직접 사용하는 경우에는 `GUISIM_BINARY`도 `.runtime/sumo-1.28.0/bin/sumo-gui.exe`의 절대 경로로 지정해 주세요. 기존 엔진에서 평가했던 수치를 새 엔진의 수치와 바로 합치지 마시고, 비교 정책을 같은 엔진·같은 평가 시드에서 다시 평가해 주세요.
