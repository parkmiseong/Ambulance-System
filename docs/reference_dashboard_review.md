## 환자별 결과

- 결과를 최근 12명으로 제한하지 않고 실행 내 모든 에피소드에 대해 보존한다.
- `에피소드:환자 ID`로 구분해 다른 에피소드의 같은 환자 ID도 별개의 사례로 처리한다.
- 중증도별 전체 결과·도착·실패·관측 종료·환자당 보상을 집계한다.
- 병원×KTAS 표는 실제 도착 환자만 세며, 배정 뒤 실패한 환자는 도착으로 계산하지 않는다.
- 에피소드·중증도·병원·결과·검색으로 필터링하고 페이지별로 조회한다.
- 상세 화면에 보고 시 Pre-KTAS, 배정 KTAS, 차량, 병원, 점유율, 적합도, 시간, 종료 사유와 보상 분해를 표시한다.
- CSV는 현재 필터에 맞는 전체 환자를 UTF-8 BOM으로 내보낸다. 페이지에 보이는 행만 내보내는 방식이 아니다.
- 실행 결과 JSON에도 전체 환자 기록을 포함한다. 완료 에피소드는 `patients_episodeN.json`으로 별도 저장한다.
- 이전 대시보드 CSV를 불러올 수 있다. 병원명은 실제 병원 데이터/저장 manifest에서 복구하고, 이전 기록에 없는 차량 ID 등은 추정하지 않는다.

## 자료와 현재 구현의 범위

자료에는 FastAPI·Node.js·Socket.IO와 단일/다중 에이전트 구조가 제안돼 있다.
이번 변경은 사용자의 웹 화면·결과 상세화 요청에 맞춰 기존 로컬 HTTP 서버와 공통 SUMO/DQN 엔진을 확장했다.
통신 스택 전체를 교체하거나 다중 에이전트 학습으로 바꾸지 않았다.

자료 5쪽의 생존율·사망률은 연구 목표다. 현재 프로젝트는 사망/생존 결과를 생성하지 않으므로
도착률이나 골든타임 비율을 생존율로 바꾸어 표시하지 않는다. 현재 연구용 보상과 시간 기준을 사용한다.
중증도 변화·임상 결과를 새로 가정하지 않고 엔진이 기록한 Pre-KTAS/KTAS를 표시한다.

119/소방 지점은 참고 위치다. 현재 `MissionManager`는 환자 위치에서 구급차를 생성해 병원으로 이동시킨다.
센터 출발→현장 도착 또는 병원→센터 복귀를 시뮬레이션한 것으로 표현하지 않는다.
